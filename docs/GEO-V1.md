# GEO-V1: источники (Китай/ОАЭ/США/Казахстан) + гео в фильтрах и рынках

Спека волны 2026-10-28 (решения зафиксированы; реализация волнами агентов,
контракты имён в этом файле ОБЯЗАТЕЛЬНЫ для бэка и фронта).

## 1. Источники

Статус на начало волны: `encar` (KR, активен), `kcar` (KR, написан),
`che168` (CN, написан, НЕ включён — селекторы сверить). Новые адаптеры —
по образцу `che168.py` (SSR-HTML) и `kcar.py` (JSON API):

| name | Страна | Сайт | Механика | Приоритет |
|---|---|---|---|---|
| `dubizzle` | AE | dubizzle.com | SSR-HTML список + карточка | P0 |
| `cars_com` | US | cars.com | SSR-HTML список | P0 |
| `kolesa` | KZ | kolesa.kz | SSR-HTML список (RU-тексты) | P1 |
| `che168` | CN | che168.com | доревизия селекторов, включение | P0 |

Правила: валюты — AED/USD/KZT/CNY → сохраняем исходную валюту и цену,
конвертация только на фронте (как KRW); адаптеры НЕ трогают
`sources/__init__.py` и `registry.py` — регистрацию делает ревизор;
`fetch(criteria, cursor)` без клиентских фильтров — фильтрует конвейер;
`country` проставляется адаптером в UnifiedListing. Япония (аукционы)
вне волны — API закрыты.

## 2. Контракт гео (имена фиксированы)

- `listings.country`: `String(2)` ISO-3166 alpha-2 (`KR`,`CN`,`AE`,`US`,`KZ`,
  `RU`…), nullable→бэкфилл по source-мапе (encar/kcar→KR, che168→CN,
  новые — своя), owner-лоты рынка → страна продавца из формы.
- `listings.city`: `String(64) | null` — только для owner-лотов (рынок).
- Миграция `0031_geo_listing_columns` (+ индекс `(country)`; фасетный
  запрос по is_active).
- API ленты: query `country=<ISO2>` (одна страна; CSV — не нужно);
  фасеты `GET /api/listings/facets` → ключ `countries: ["KR","CN",…]`.
- `ListingOut`: поля `country`, `city`.
- Рынок: `POST /api/market/lots` и PUT принимают `country` (обязателен
  для owner-лотов, enum известных + свобода), `city` (опционален);
  `GET /api/market/lots?country=` фильтр; MyLotOut несёт оба поля.
- Калькулятор `DeliveryIn.country` (default `KR`): ставки логистики
  по странам — отдельный модуль констант (порт загрузки, порт выгрузки,
  фрейт $, сроки дней) для KR/CN/AE/US/KZ; таможня ЕАЭС неизменна
  (считается уже существующим кодом от цены/объёма/возраста).

## 3. UI/UX (решения)

- **Лента**: быстрые чипсы-страны с флагами (🇰🇷 Корея · 🇨🇳 Китай · 🇦🇪 ОАЭ ·
  🇺🇸 США · 🇰🇿 Казахстан) в строку после пресетов; в шите фильтров —
  сегмент «Страна» (один выбор + «Все»). Смена страны — новый запрос,
  кэш ленты не смешивается (ключ кэша уже включает query).
- **Карточка ленты**: бейдж-флаг+код страны рядом с источником
  (`🇨🇳 CN · che168`); у owner-лотов — город (`🇷🇺 RU · Москва`).
- **PDP**: строка «Страна: 🇦🇪 ОАЭ, Дубай» в блоке характеристик.
- **SellCar (шаг «Авто»)`: селект страны (RU по умолчанию — внутренний
  рынок) + поле «Город» (текст, обязательное при стране RU? нет —
  опционально, но рекомендуемо)».
- **Рынок/витрина**: фильтр-строка стран сверху (чипсы), карточки с
  флагом; партнёрская витрина — те же бейджи.
- **Калькулятор**: сегмент страны отправки (KR/CN/AE/US/KZ), подпись
  маршрута «Пусан → Владивосток» под результатом.
- Гость/PRO/Business — гео без тарифных отличий; AI-диалог понимает
  страну словами («ищу в Дубае» → country=AE — доизучение NLU вне волны,
  в AI.md не обещаем).

## 4. Волны

- A `geo-backend`: миграция+модель+фильтр+фасеты+рынок+калькулятор.
- B `sources-uae-us`: dubizzle + cars_com (+фикстуры-тесты).
- C `sources-kz-che168`: kolesa + ревизия che168 (+включение в БД-сид).
- D `frontend-geo`: фильтры/чипсы/бейджи/PDP/SellCar/рынок/кальк.
- E `uiux-doc`: docs/UIUX-GEO.md — развёрнутый дизайн-док по §3.
- Ревизор (главный агент): регистрация адаптеров, сид источников в БД,
  сквозные тесты, деплой, browser-use прогон.
