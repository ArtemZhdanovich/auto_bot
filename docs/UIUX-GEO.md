# UIUX-GEO: дизайн волны гео (страны в ленте, карточке, PDP, продаже, калькуляторе)

Развёрнутый дизайн-док волны E `uiux-doc` по решениям GEO-V1 §3.
Среда: Telegram Mini App, mobile-first (вьюпорт ~390–430px), тёмная/светлая
темы через токены `frontend/src/index.css` (`--tg-theme-*` + `data-theme`),
навигация NAV-V2: Главная `/` = сегмент «Лента | AI», Авто `/auto` =
«Избранное | История | Мои объявления»; калькулятор `/calc` — стек-экран
без места в таб-баре (вход ссылками из Ленты и PDP).

Принципы, на которые опираемся (и проверяем каждое решение ниже):

- **Фиттс**: тап-цели ≥ 44px — в проекте уже есть токен `--touch-min: 44px`
  и mobile-media, поднимающий `.chip` до 44px высотой; новые гео-контролы
  наследуют это правило автоматически, ничего «компактнее» не проектируем.
- **Хик**: в чипсах и сегментах стран — не более 5–7 вариантов (5 стран +
  «Все» = 6); мультивыбор стран отвергнут (§2.4).
- **Гештальт**: фильтры сгруппированы секциями (в шите уже «Авто / Цена и
  год / Пробег»), гео — отдельная ось фильтрации, отдельный ряд чипсов и
  отдельная секция шита, а не «ещё один чипс в общем ряду».
- **F-паттерн карточки**: фото → заголовок → мета-строка → цена; страна
  живёт в мета-строке (третья «горячая» зона сканирования), а не бейджем
  на фото, где место только для статусных меток.

## 1. Цели и сценарии (персоны)

Цель волны: из «корейского агрегатора» стать мульти-страновым каталогом с
честным landed cost — пользователь выбирает страну в один тап, видит её на
каждой карточке и сразу считает доставку от этой страны.

**П1 «Перекуп Пётр, 34»** — ищет лот в ОАЭ/США. Заходит в ленту, тапает чипс
«🇦🇪 ОАЭ» (1 тап вместо открытия шита и селекта — Фиттс: частотное действие
должно быть самым коротким), сортирует «Цена ↑», открывает карточку, из PDP
считает доставку с `country=AE`. Боль «не та страна»: сегодня корейские лоты
перемешаны с будущими источниками без опознавательных знаков.

**П2 «Частница Марина, 41»** — продаёт машину в своём городе. FAB «+» →
шаг «Авто»: страна уже `RU` по умолчанию (ей не нужно ничего выбирать — Хик:
убрали выбор, который нужен 90% продавцов внутреннего рынка), поле «Город» —
опционально. Покупатель видит её лот с бейджем «🇷🇺 RU · Тверь» и не пишет
«а где машина?» в чат.

**П3 «Покупатель Тимур, 27»** — сравнивает landed cost по странам. Смотрит
один класс авто в Корее и ОАЭ, из каждого PDP жмёт «Посчитать доставку» —
калькулятор уже развёрнут на нужную страну, в подписи маршрут и срок
«Пусан → Владивосток, ~15–25 дней» vs «Дубай → Новороссийск, ~40–55 дней».
Решение принимается без ручного ввода параметров маршрута.

Общие job-stories: «Когда я открываю ленту, я хочу за один тап сузить её до
страны, чтобы не смотреть неактуальные для меня юрисдикции»; «Когда я вижу
карточку, я хочу понять страну до открытия»; «Когда я считаю доставку, я
хочу, чтобы страна уже была выбрана той, откуда машина».

## 2. Лента

### 2.1 Строка чипсов-стран

Гео — вторая ось фильтрации (первая — цена/год в пресетах). По гештальту
(закон близости) оси разведены по рядам: смешение «до $10 000» и «🇦🇪 ОАЭ»
в одном ряду ломает сканирование и делает активный фильтр нечитаемым.

```text
┌───────────────────────────────────────────────┐
│ Фильтры ·2  [Новые ▾]      512 АВТО · НОВЫЕ СВЕРХУ │  суббар (.feed-head__row)
│ (Все)(до $10k)($10–20k)(2022+)(🏪 Рынок)(🔔 Со…)  │  ряд 1: пресеты + сигналы
│ 🇰🇷 Корея · 🇨🇳 Китай · 🇦🇪 ОАЭ · 🇺🇸 США · 🇰🇿 Казахстан│  ряд 2: СТРАНЫ (новое,
├───────────────────────────────────────────────┤  скролл-snap, маска краёв)
│ [SkeletonList ×4 …]                           │
```

Ряд — тот же контейнер `.feed-head__chips` (scroll-snap + маска по краям
уже показывают «ряд продолжается»). «Все» в ряд НЕ добавляем: снятие страны
— повторный тап по активному чипсу (как toggle «🏪 Рынок»), 5 чипсов = 0
лишних вариантов (Хик: 5 ≤ 7; в шите, где нет тапа-снятия, «Все» нужен).

### 2.2 Состояния чипсов

- **active**: `.chip--active` (заливка `--accent`), `aria-pressed="true"`,
  повторный тап снимает страну (`setQuery(q => ({...q, country: undefined}))`).
- **обычный**: `.chip`, `aria-pressed="false"`.
- **disabled (нет лотов)**: страна отсутствует в фасете `countries` →
  `.chip:disabled` (opacity .45 уже есть в CSS) + `title`/`aria-label`
  «Китай: лотов пока нет». Чипс остаётся видимым — источник работает,
  лоты появятся; скрытие ломало бы модель «5 стран» в голове пользователя.

Размеры: высота ≥ `--touch-min` на мобиле (наследует mobile-media для
`.chip`), флаг 15px слева от подписи — код+слово, не только флаг (принцип
«цвет + текст» из 03-content-a11y: дальтоник и SR читают слово «ОАЭ»).

### 2.3 Поведение при смене страны

1. `country` попадает в `FeedQuery`; `setQuery` триггерит существующий
   эффект `load(query, true)` — новый запрос, **пагинация сбрасывается**
   (`offset = 0`, курсор с нуля), старые карточки заменяются.
2. На время загрузки — `SkeletonList count={4}` в `.feed-grid`, счётчик-eyebrow
   скрывается (`!loading`), как сегодня. Никаких «старых карточек рядом с
   новыми»: смешение юрисдикций и цен в разных валютах — главный источник
   жалоб «не та страна».
3. Скролл области `.feed-scroll` — наверх (viewport-scroll: лента крутится
   внутри своей области, `scrollTop = 0`).
4. Кэш возврата не смешивается: ключ кэша уже включает query (GEO-V1 §3) —
   вернувшись из PDP, пользователь видит ту же страну и позицию.
5. `haptic("light")` на выбор — тот же отклик, что у `pickRegion` в Calc.
6. **Deep-link `?country=AE`**: расширенная `deepLinkQuery()` читает
   `country` тем же паттерном, что `make/model` (применение и на живом
   keep-alive экране, очистка URL через `history.replaceState`) — ссылки из
   бота «Смотреть ОАЭ» и будущий AI-поиск работают без нового механизма.

### 2.4 Шит фильтров — секция «Страна»

Секция «Страна» — **первая** в шите (`.feed-panel__section`, как «Авто»):
страна — самый грубый фильтр (от большого к малому), задаёт юрисдикцию цен
и логистики. Под ней — радио-сегмент:

```text
│ Страна                                        │  .feed-panel__section
│ ( Все )(🇰🇷 KR)(🇨🇳 CN)(🇦🇪 AE)(🇺🇸 US)(🇰🇿 KZ) │  сегмент, role=tablist
```

**Почему не мультивыбор** (решение зафиксировано, обоснование):
- Хик: 2^5 комбинаций стран — осознанный выбор растёт экспоненциально;
  сегмент из 6 пилюль сканируется мгновенно.
- Смысл: страна — это юрисдикция (валюта источника, маршрут, сроки
  доставки). «ОАЭ + Корея одновременно» не отвечает ни на один вопрос
  пользователя; сравнение стран — сценарий P3, и он решается калькулятором.
- Контракт: API принимает одну страну, CSV не нужен (GEO-V1 §2) — UI не
  должен обещать то, чего нет в бэке.
- Фиттс: пилюли сегмента ≥ 44px высотой; чекбоксы такой площади съедят
  пол-экрана шита.

Счётчик результатов: живой футер шита «N авто найдено» уже пересчитывает
`GET /listings?…&limit=1` по черновику — `country` входит в `draft` и в
`buildListParams`, отдельной логики не нужно. `aria-live="polite"` уже есть
(`.feed-sheet__count`) — SR объявляет число после debounce.

## 3. Карточка ленты

### 3.1 Место бейджа страны

```text
┌──────────────────────────────┐
│ [ фото 16:9 ]          ♡  (7)│
│  ⬇️ −7%  🧾 Чек  👤 Частник   │ ← статусные бейджи (lcard__badges)
├──────────────────────────────┤
│ Hyundai Grandeur             │ ← F: заголовок (2 строки max)
│ 2022 · [🇦🇪 AE · Дубай] · 45 т. км │ ← F: мета-строка (новое — geo-badge)
│ $21 400                      │ ← F: цена
│ ≈ 2,1 млн ₽                  │
│ 2.5 л · Бензин · АКПП        │
└──────────────────────────────┘
```

Решение: страна — **инлайн-бейдж внутри мета-строки**, не пилюля на фото.
Обоснование: на фото живут статусные метки («Исчезло», «−N%», «Чек»,
«Рынок») — один смысл на одно место (гештальт: не смешиваем «состояние
лота» с «географией лота»); F-паттерн — мета-строка и так сканируется
третьей зоной, гео встраивается в существующий ритм чтения без новой
строки. GEO-V1 §3 формулирует это как «бейдж-флаг+код рядом с
источником» — рендерим ту же сущность компонентом `.geo-badge`.

Форматы (вместо хардкод-словаря `SOURCE_META` берём `listing.country`):
- внешний источник: `2023 · 45 000 км · [🇨🇳 CN · che168] · 21.10`
- owner-лот рынка: `2023 · 45 000 км · [🇷🇺 RU · Москва]` (город вместо
  имени источника — у owner-лотов источника нет).

### 3.2 Контраст в тёмной теме и длина строки

- `.geo-badge`: фон `var(--bg-secondary)`, текст `var(--text-secondary)` —
  оба токена переопределены в `:root[data-theme="dark"]` (#171a20 / #9aa4b2,
  ≥ 6:1), т.е. контраст гарантируется токенами, а не новыми цветами. Флаг —
  цветной в обеих темах (эмодзи рендерит система), код «AE» дублирует его
  текстом для дальтоников и монохромных тем Telegram.
- Длина: мета-строка — одна строка с ellipsis (`.lcard__meta` уже
  `white-space: nowrap`), поэтому формат короткий: **код страны + город**,
  не полное имя («AE · Дубай» ≤ 16 симв., а не «Объединённые Арабские
  Эмираты, Дубай»). Полная строка целиком ≤ ~44 симв.: `2023 · 45 000 км ·
  [🇦🇪 AE · Дубай]` помещается на 390px; без города — только код.
- `aria-label` карточки дополняется: «Hyundai Grandeur, 2022, $21 400,
  ОАЭ, Дубай» — SR называет страну словом, флаг `aria-hidden`.

## 4. PDP: блок «География»

Отдельная `panel` **после «Характеристик»** (гештальт: атрибуты машины —
одна группа, география+логистика — другая; смешивать «Кузов: седан» и
«Порт: Джебель-Али» в одном списке — путаница):

```text
┌ География ────────────────────────────┐
│ Страна            🇦🇪 ОАЭ              │  info-row
│ Город / порт      Дубай               │  info-row
│ Маршрут           Дубай → Новороссийск │  info-row + подпись
│                   → ваш город          │
│ Срок              ~40–55 дней, море    │
│ [ 🚚 Посчитать доставку → ]            │  .pdp-cta__link (не primary)
└───────────────────────────────────────┘
```

- Строки — существующий паттерн `.info-row` (`info-row--spec` на мобиле:
  подпись сверху, значение ниже); значения только из `ListingOut`
  (`country`, `city`) и констант маршрута бэка.
- Маршрут и срок — из модуля ставок логистики (порт загрузки/выгрузки,
  дни; GEO-V1 §2). Для owner-лотов RU блок показывает «Страна 🇷🇺 Россия /
  Город Тверь» **без** маршрута и кнопки — внутреннему рынку доставка
  из-за рубежа не применима; пустых строк не рисуем.
- **Связь с калькулятором**: кнопка-ссылка «Посчитать доставку →» — класс
  `.pdp-cta__link` (не primary: на PDP primary один — «Связаться с
  менеджером», P2), ведёт на существующий паттерн
  `/calc?price=…&year=…&cur=…` **+ `&country=AE`**. Существующая ссылка
  «Доставка и растаможка →» в CTA-карточке получает тот же `&country=` —
  обе точки входа прокидывают страну: одна контекстная (в «Географии»),
  вторая «под пальцем» в sticky-CTA; обработчик один.
- Мобильный порядок: блок стоит в DOM после «Характеристик», до «Данных
  объявления» — гео важнее дат отслеживания (частотный вопрос «откуда
  машина?» решается до скролла вглубь).

## 5. SellCar: страна и город

Шаг 1 «Авто» (`.sell-grid`) получает два поля:

```text
│ Марка *        │ Модель *      │
│ Год выпуска *  │ Пробег, км    │
│ Страна *                    [🇷🇺 RU ▾] │  select, дефолт RU
│ Город (необязательно)       [Москва  ] │  input + маска
│ Топливо        │ КПП           │
```

- **Дефолт `RU` — почему**: owner-лот = страна продавца из формы (GEO-V1
  §2), рынок волны — внутренний; подавляющее большинство продавцов в РФ,
  и дефолт убирает лишний выбор (Хик). Селект: известные страны enum
  (RU/KZ/… + свобода), обязательное поле — `country` обязателен для
  owner-лотов контрактом.
- **Маска города**: буквы (кириллица/латиница), пробел, дефис;
  `maxLength 64` (контракт `String(64)`); автокапитализация первого
  символа; placeholder «Москва». Трансформацию делаем в `onChange` —
  цифры и символы просто не вводятся (ошибки до сабмира не копим).
- **Опционально, но рекомендуемо** (GEO-V1 §3): «Далее» не блокируем.
  Вместо навязанной ошибки — пункт в живом чек-листе «Качество объявления»
  (шаг 3, `localQualityChecks`): «Указан город» с tip «Покупатели ищут
  рядом с собой» — мягкая мотивация тем же механизмом, что и «фото ≥ 3».
- **Ошибка валидации** (единственный красный кейс — длина/пустая страна):
  `role="alert"` в `.sell-field__error`: «Укажите страну», «Город — буквы,
  до 64 символов». Тексты в словаре инлайн-валидации экрана (как
  `validateCar`).
- **Превью объявления** (`.sell-preview`): `previewMeta` дополняется
  гео-частью — «35 000 км · Бензин · АКПП · [🇷🇺 RU · Тверь]» — превью
  повторяет мета-строку будущей карточки ленты один-в-один (единый
  словарь: что увидел в превью, то увидят покупатели).
- Оба поля — в черновик `DraftData` (sessionStorage `autobot.sellDraft`) и
  в edit-режим из `MyLot` (контракт: `MyLotOut` несёт `country`/`city`).

## 6. Рынок и витрины

- **Лента рынка**: чипс «🏪 Рынок» (`source=market`) и строка стран —
  независимые оси: «🏪 Рынок + 🇷🇺» = внутренний рынок в РФ, «🏪 Рынок +
  🇰🇿» = партнёры из Казахстана. В шите секция «Страна» одна на оба

## 7. Калькулятор

```text
│ 🚚 Доставка «под ключ»                        │
│ 🇦🇪 Дубай → Новороссийск → вам                 │  feed-header__counter
│                                               │
│ Юрисдикция:  (🇷🇺 По РФ)(🇧🇾 По РБ)             │  существующие чипы
│ Страна отправки:                               │
│ (🇰🇷 KR)(🇨🇳 CN)(🇦🇪 AE)(🇺🇸 US)(🇰🇿 KZ)         │  НОВОЕ, role=tablist
│ Цена $ [18 000]  Объём [2 000] (1600)(2000)…  │
│ [ Рассчитать ]                                 │
│ …                                              │
│ Итого «под ключ»        2 410 000 ₽            │
│ 🚢 Море Дубай → Новороссийск, ~40–55 дней,     │  calc-note + срок
│ далее автовоз до вашего города.                │
```

- **Сегмент страны** — отдельная `.chip-row` (не смешиваем с юрисдикцией
  РФ/РБ: то «куда везём», это «откуда везём» — гештальт-разделение групп;
  подписи строк делают различие явным). 5 стран без «Все»: калькулятор
  всегда про конкретную страну, дефолт виден активным чипсом.
- **Дефолт**: из query `&country=` (переход из PDP), иначе `KR` —
  контракт `DeliveryIn.country` default KR (GEO-V1 §2). Префилл живёт в
  существующем эффекте «query изменился → перекладываем поля и считаем»
  (keep-alive), второй лот из другой страны считается со своей страной.
- **Маршрут-подпись и сроки**: заголовок (`feed-header__counter`) меняет
  «Корея → Владивосток → вам» на маршрут страны («Дубай → Новороссийск →
  вам»); под результатом `calc-note` получает срок из констант: «~15–25
  дней» (KR), «~40–55 дней» (AE/US) — цифры из модуля ставок, не хардкод
  на фронте.
- **Состояние загрузки**: существующее — кнопка «Считаю…» (disabled) +
  `SkeletonCard` в `.calc-result`; смена страны с готовым результатом
  пересчитывает только при `result.country !== country` (как `pickRegion`).
- **Ошибка неизвестной страны** (бэк не знает ставок): человеческий текст
  через маппинг `apiErrorText`: «Для этой страны ставок пока нет —
  посчитайте от Кореи 🇰🇷 или уточните у менеджера» + активным становится
  KR. Никаких сырых `detail` (03 §3.2). Блок `.calc-error role="alert"`.

## 8. Состояния

- **Пустая страна** (запрос ок, лотов 0): `EmptyState` по центру области
  (`.feed-states`), стиль «Chats» (emoji + title + текст + CTA):

```text
│              🗺                              │
│         В ОАЭ пока пусто                    │
│  Лоты из ОАЭ появляются каждый день.        │
│  Посмотрите Корею — там сейчас 500+ авто,   │
│  или подпишитесь на сигнал.                 │
│       [ Сбросить страну ]                   │
```

  CTA «Сбросить страну» сбрасывает **только** `country` (мягкий сброс:
  остальные фильтры/сортировка сохраняются) — полный «Сбросить фильтры»
  остаётся в шите и в текущем пустом состоянии. Обоснование: пользователь
  терял бы выставленные цену/год из-за пустой страны — наказание за
  исследование (Nielsen: система должна прощать).
- **Ошибка фасетов**: `GET /listings/facets` упал → чипсы стран рендерим из
  константного списка 5 стран (без disabled-логики), лента работает;
  тихо, без тоста — фасет оптимизация, не блокер. Если страна реально
  пуста, пользователь увидит пустое состояние выше — то же поведение, что
  у зависимых селектов марка→модель сегодня (`catch → []`).
- **Гость**: гео без тарифных отличий (GEO-V1 §3) — чипсы, шит, бейджи и
  калькулятор доступны; «🏪 Рынок» гейтится как сейчас. Гостевой логин-
  промпт срабатывает только на действии, требующем аккаунта (избранное/
  контакт) — гео-просмотр не гейтим.

Доступность (по образцам проекта — `chats-seg`, «🏪 Рынок», бейдж чатов):

- чипс страны: `aria-pressed` + `aria-label="Страна: ОАЭ"` (флаг — 
  `aria-hidden`, смысл несёт слово); disabled — `aria-disabled="true"` и
  причина в label («лотов пока нет»);
- сегменты (шит, калькулятор): контейнер `role="tablist"` с
  `aria-label="Страна"`, кнопки `role="tab"` + `aria-selected` — точь-в-точь
  паттерн «Диалоги | Переговорные»;
- счётчик результатов в шите — `aria-live="polite"` (уже есть у
  `.feed-sheet__count`);
- мета-строка карточки попадает в `aria-label` карточки словами («…, ОАЭ,
  Дубай»), geo-badge с флагом — `aria-hidden` для иконки, текст читается;
- контраст: фон/текст бейджа только через тему-зависимые токены; код
  страны дублирует флаг текстом (не только цвет).

## 10. Метрики успеха

1. **Доля сессий с фильтром страны** ≥ 25% в первые 2 недели после релиза
   (событие `feed_country_set {country, surface: chip|sheet|deeplink}`).
   Ожидаемо `chip` ≥ 80% — если меньше, ряд чипсов не находят (вернёмся к
   расположению).
2. **Конверсия PDP → «Посчитать доставку»** (событие `pdp_calc_open
   {country}`) ≥ 8% просмотров PDP; далее `calc_completed {country}` ≥ 60%
   от открывших. Это главный сигнал, что блок «География» + прокидывание
   `country` работают.
3. **Жалобы «не та страна»** — 0 в тренде: ручной подсчёт по чатам
   поддержки + тег в переговорных. Прокси-метрика: доля возвратов из PDP в
   ленту со сменой страны (пользователь «не понял, откуда машина») —
   должна падать.
4. Вспомогательные: CTR чипсов стран по странам (баланс парковки источников),
   доля тапов в disabled-чипсы (< 3% — значит фасеты честные), доля пустых
   состояний страны (< 15% сессий с фильтром), заполненность «Город» в
   новых объявлениях ≥ 50% (мягкий чек-лист, не обязаловка).
