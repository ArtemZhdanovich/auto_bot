## Главное в 10 тезисах

1. **Рефакторинг нельзя начинать с текущего дерева.** Оно не импортируется:
   `app/api/dialog.py` импортирует `RedisDep` из `app/core/deps.py`, где его
   больше нет. Плюс в конце `app/main.py` создаётся второй `FastAPI(...)`,
   который затирает приложение со всеми 68 маршрутами.
2. **22 тест-модуля не собираются**, из них 7 — вставленные фрагменты без
   `import pytest` и без фикстур (`tests/test_favorites.py` и др.).
   «773 теста собрано» в текущем виде не означает «зелёные тесты».
3. **Внешнее AI-ревью по ссылке устарело.** Оно делалось по снимку до фиксов:
   `deps_internal.py` уже fail-closed, `favorites.py` уже с лимитами,
   `DISTINCT ON` и `model_copy`, `leads.py` уже с `Idempotency-Key`,
   `partners.py` — с атомарным `UPDATE ... RETURNING`. Повторно «чинить» это
   нельзя — сломаете работающее.
4. **Главный архитектурный долг — не баги, а границы.** 4 933 строки в
   `app/api/` содержат бизнес-логику, SQL и `commit()`; 44 `session.commit()`
   разбросаны по приложению; 17 мест создают сессию сами через
   `session_factory()`.
5. **Dishka даёт то, чего не даёт `Depends`:** один контейнер на FastAPI +
   aiogram + FastStream, разные скоупы (`APP` — engine/брокер, `REQUEST` —
   сессия/UoW/use case), подмена провайдеров в тестах без БД.
6. **FastStream заменяет самописный `TaskWorker`** (409 строк), сохраняя
   RabbitMQ и топологию `tasks`/`fetch`/`send`/`dead_letter`, но добавляя
   типизированные сообщения, идемпотентность и корректный shutdown.
7. **События — только после commit.** Базовый вариант: collect/flush в
   памяти. Для денег (`charge_lead`, платежи) — transactional outbox:
   событие пишется в ту же транзакцию, что и данные, релей публикует после.
8. **`lazy="raise"` в текущей схеме неприменим:** в `models.py` вообще нет
   `relationship()` (0 штук). Проблема не в ленивой загрузке, а в ручных
   запросах в циклах и в записи на read-path (`enrich_listing_specs` в GET).
9. **Ключевая производительность:** `WHERE price/1350` не использует индекс
   (нужен хранимый `price_usd`), `OFFSET` на ленте + `count(*)` на каждый
   запрос, отсутствие keyset-курсора, новый `httpx.AsyncClient` на каждый
   вызов в боте.
10. **Порядок работ важнее скорости:** сначала зелёный baseline и
    характеризационные тесты, потом домен, потом UoW/DAO, потом Dishka, и
    только затем FastStream. Каждая фаза обратима.

`trace_id`.

## Границы этого пакета

Документы **не меняют код**. Это проект и план; правки в `app/` не вносились,
потому что дерево содержит незакоммиченную работу (38 файлов) и любое
изменение сейчас конфликтует с ней. После согласования начинаем с фазы 0.
