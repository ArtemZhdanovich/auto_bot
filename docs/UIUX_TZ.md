## 1. Принципы и дизайн-система

### 1.1. Три поверхности — один продукт

| Поверхность | Аудитория | Контекст | Приоритет |
|---|---|---|---|
| **Mini App + сайт** | Покупатель, перекуп | Мобильный, Telegram webview, десктоп | B2C |
| **Админ-панель** | Владелец, оператор | Десктоп, браузер | Внутренний |
| **Партнёрский ЛК** | Салон, брокер | Десктоп, браузер | B2B |
| **Telegram-бот** | Покупатель | Мобильный, мессенджер | B2C |

**Правило:** одна дизайн-система, три разных плотности. Mini App — мобильный,
крупные тапы. Админка и ЛК — десктоп, плотные таблицы. Бот — текст и inline-кнопки.

### 1.3. Иконки и графика

- **Иконки:** `lucide-react`. Таббар — SVG, не эмодзи.
- **Placeholder-иллюстрации:** простые SVG (empty/error state).
- **Фото авто:** обязательны в Feed и Listing.

### 1.4. Роли и доступы в UI

| Роль | Видит | Роут |
|---|---|---|
| Гость (вне TG) | Read-only лента, Login | `/` |
| User | Feed, Listing, Filters, Favorites, AiSearch, Profile | `/app/*` |
| Partner | Partner LK | `/partner/*` |
| Admin | Admin panel | `/admin/*` |

**Правило:** таббар Mini App не содержит ссылок на `/partner` и `/admin`.

### 1.5. Общие принципы UX

1. **Скорость важнее красоты.** Skeleton вместо Spinner, оптимистичные обновления.
2. **Один экран — одно действие.**
3. **Всегда есть fallback.** Нет LLM — кнопочный режим. Нет фото — placeholder.
4. **Обратная связь.** Каждое действие — haptic (в TG), toast или визуальный отклик.
5. **Данные — на первом месте.** Цена, год, пробег — крупно.
6. **Мобильный — основной.** Даже админка должна открываться с телефона.

## 2. Mini App (пользовательская часть)

### 2.1. Структура

- Онбординг (один раз, флаг в БД `users.onboarded_at`): приветствие → выбор
  роли (покупатель/перекуп/салон) → выбор стран.
- Таббар (5 вкладок, SVG-иконки): Feed, Filters, Favorites, AiSearch, Profile.
- Полные экраны: Listing, Login, Onboarding.
- Десктоп (`>= 768px`): sidebar слева вместо таббара, лента в 2–3 колонки,
  Listing в 2 колонки (галерея слева, инфо справа), `--content-max: 1200px`.

### 2.2. Feed (лента)

**Шапка (sticky):** заголовок, страны-чипсы (горизонтальный скролл),
счётчик «2 341 авто • Новые» (сортировка).

**Чипсы фильтров — динамические:** «Все» (default), сохранённые фильтры
пользователя (`GET /filters`), быстрые пресеты («до $20k», «2022+», «из Кореи»). 

**Карточка объявления:** фото 16:9 (lazy load, fallback-заглушка при отсутствии),
марка+год (крупно), цена крупно, вторичные параметры (пробег/топливо/КПП/привод),
локация + источник, кнопки: избранное (haptic), открыть.

**Поведение:** бесконечный скролл (IntersectionObserver), skeleton-карточки
при загрузке, pull-to-refresh, тап → Listing.

**Empty state:** SVG-иллюстрация + «Ничего не найдено» + CTA «Изменить фильтры».
**Error state:** «Не удалось загрузить» + «Повторить».

### 2.3. Listing (карточка)

- Галерея: свайп, точки-индикаторы, зум; счётчик «1 / 8».
- Характеристики таблицей: год, пробег, двигатель, КПП, привод, кузов, цвет,
  VIN, локация, источник.
- Стоимость «под ключ» (если рассчитывается бэкендом) + калькулятор.
- «Похожие» — горизонтальный скролл 3–5 карточек.
- Sticky-bottom «Связаться с менеджером» → форма → `POST /api/leads`.
- Main Button Telegram: «Связаться»; Back Button: возврат в Feed.
- Избранное: toggle + haptic; «Открыть у источника».

### 2.4. Filters

Два режима: **список** (сохранённые фильтры с delete/edit) и **редактор**.

Редактор: название, страна → марка → модель (каскадные селекты), годы
(от/до), цена до, пробег до, топливо, КПП, привод, кузов; режим уведомлений
(instant/digest/off). «Тихие часы» — **[бэкенд]**, в MVP не показывать.

Валидация: хотя бы марка/модель. Лимиты по тарифу (Free 3 / Pro 20 /
Business ∞) — при превышении попап «Обновите тариф».

### 2.5. AiSearch

Чат-интерфейс (уже есть). Улучшения:
- Критерии — отдельная карточка человеко-читаемым текстом (не JSON).
- Индикатор «печатает» (анимированные точки) пока LLM отвечает.
- «Запустить поиск» → финализация → переход в Feed с фильтром.
- LLM недоступна → «AI временно недоступен. Используйте фильтры» + кнопка в Filters.

### 2.6. Favorites

Фото в карточках, сортировка (по дате/цене), удаление, заметки (позже),
экспорт CSV (позже).

### 2.7. Profile

Профиль, тариф + лимиты, покупка Stars (есть). Добавить: реферальная ссылка
+ статистика **[бэкенд]**, история платежей **[бэкенд]**, экспорт данных /
удаление аккаунта **[бэкенд]**, настройки уведомлений (дублируют бота).

### 2.8. Онбординг (3 шага)

1. Приветствие + имя из TG-контекста → «Начать».
2. Роль: Покупатель / Перекуп / Салон-брокер.
3. Страны-источники (чекбоксы) → «Готово».

Флаг — `users.onboarded_at` в БД (не sessionStorage). Повторный онбординг —
из Profile.

### 2.9. Login (вне Telegram)

Email+пароль (есть) + magic link (API уже поддерживает) как альтернатива
и как «Забыли пароль?». Валидация на лету, показ/скрытие пароля.

### 2.10. Переиспользуемые компоненты

| Компонент | Где | Что |
|---|---|---|
| `ListingCard` | Feed, Favorites, Похожие | Фото + цена + параметры |
| `FilterChip` | Feed, Filters | Чипс с активным состоянием |
| `SkeletonCard` | Feed, Favorites | Заглушка при загрузке |
| `EmptyState` / `ErrorState` | Везде | Иллюстрация + текст + CTA |
| `Toast` | Везде | Всплывающее уведомление |
| `Tabbar` / `Sidebar` | Mobile / Desktop | Навигация |
| `Gallery` | Listing | Галерея со свайпом |
| `CriteriaCard` | AiSearch | Критерии человеко-читаемо |

## 3. Админ-панель

### 3.1. Принципы

- Десктоп-first, плотные таблицы, минимум декора.
- Write-операции — с подтверждением; каждое write-действие — в audit log
  (таблица `admin_actions`) **[бэкенд: миграция]**.
- Auth MVP: вход по `X-Internal-Token` (экран `/admin/login`, токен в памяти
  сессии). Таблица `admin_users` + JWT `role=admin` — позже **[бэкенд]**.

### 3.2. Структура

Sidebar 240px: Дашборд, Источники, Партнёры, Лиды, Юзеры, Аналитика, Алерты,
Логи. Контент `max-width: 1200px`. AI-помощник — плавающий виджет (фаза 4).

### 3.3. Дашборд

KPI-карточки (юзеры всего/за 24ч, лиды 24ч, активные источники, алерты),
график лидов за 7 дней (`analytics_events`), статус сервисов (`/health/detailed`),
последние алерты, топ источников.

### 3.4. Источники

Таблица: имя, тип, enabled, cron, circuit breaker, last success, действия
(⚙️ конфиг, ▶️ fetch). Детали: статус, конфиг JSON (валидация), действия
«Включить / Fetch now / Сбросить CB / Изменить», последние ошибки.

### 3.5. Партнёры

Таблица: имя, план (`starter/pro/salon` — реальные значения из
`PartnerPlan`), квота/день, использовано сегодня (`claimed_today`), статус.

Детали: основное, API-ключ (префикс + last_used_at; ротация с подтверждением,
отзыв), статистика по feedback (accepted/returned/junk/deal), последние лиды,
действия (изменить план/квоту, приостановить).

Создание партнёра: название, контакт, план, квота → после создания — экран
«Ключ показывается один раз» с копированием и предупреждением.
Баланс/биллинг — **[бэкенд]**, в MVP не показывать.

### 3.6. Лиды

Таблица: ID, юзер, авто, статус (new/claimed/accepted/returned/junk/deal),
партнёр, дата. Фильтры: статус, партнёр, дата. Детали: юзер, авто,
qualification (бюджет/срок/предоплата), история. Экспорт CSV.

### 3.7. Юзеры

Таблица: TG ID, username, tier, фильтры, лиды, последний визит. Поиск,
экспорт. Детали: профиль, фильтры, диалоги; действия: сбросить tier,
заблокировать, экспорт данных, удалить **[бэкенд: часть эндпоинтов]**.

### 3.8. Аналитика

Воронка (`analytics_events`): регистрация → открыл AI → завершил поиск →
лид → claim → deal. Retention D1/D7/D30, конверсии (Free→Pro, Лид→Claim,
Claim→Deal). SQL-дашборды — см. backlog P2.

### 3.9. Алерты и Логи

Алерты: лента (источник/CB, RAG latency, DLQ) + настройки порогов.
Логи: audit (`admin_actions`): кто/что/над чем/payload/результат/timestamp.

## 4. Партнёрский ЛК

### 4.1. Принципы

- Десктоп-first, открывается на планшете (breakpoint 768px: sidebar →
  выезжающее меню, таблицы → карточки).
- Быстрые действия: claim в 1 клик, feedback в 2.
- Изоляция: только свои лиды/квота. ПД — только после claim (уже так в API).
- Вход MVP: **по API-ключу** (`pi_…` → сессия). Email+пароль — позже
  **[бэкенд]**.

### 4.2. Структура

Sidebar: Дашборд, Пул лидов, Мои лиды, API-ключ, Биллинг (заглушка «Скоро» —
**[бэкенд]**).

### 4.3. Дашборд

Карточки: квота (использовано/лимит за сегодня), claimed за месяц,
acceptance rate, доступно в пуле. Последние лиды. Всё из `GET /api/partner/me`.

### 4.4. Пул лидов (ключевой экран)

Таблица: авто (марка/модель/годы), бюджет, срок покупки, готовность к
предоплате, [Claim]. До claim — **никаких ПД** (API и так не отдаёт `user_id`).
Фильтры: марка/модель, бюджет, срок, предоплата. Сортировка: по дате (default).
Score квалификации — **[бэкенд]**, когда появится, добавить сортировку.
Массовый claim — позже **[бэкенд: batch-эндпоинт]**.

Поведение: Claim → 200: тост «Лид захвачен», ПД открылись в «Мои лиды»;
409 «Лид уже занят» — обновить строку; 429 «Дневная квота исчерпана».

### 4.5. Мои лиды

Таблица: ID, авто, статус, дата, [Feedback]. Детали после claim: имя,
Telegram/контакт, комментарий, qualification.

**Feedback — обязателен:** accepted / returned / junk / deal (+ сумма сделки
для deal, комментарий) → `POST /leads/{id}/feedback`.

### 4.6. API-ключ

Префикс `pi_****xxxx`, создан, last_used_at. «Ротировать ключ» с
подтверждением («старый ключ перестанет работать немедленно»). Минимальная
документация API (`/api/partner/*`).

## 5. Telegram-бот

### 5.1. Принципы

- Тонкий клиент над backend; вся логика в API.
- AI-диалог — ядро; кнопочный fallback обязателен.
- Минимум команд; всё через меню; Mini App — для тяжёлого UI.

### 5.2. Команды

Публичные: `/start`, `/menu`, `/help`, `/reset`, `/stop`, `/resume`,
`/subscribe`. Скрытые: `/app`, `/filters`, `/favorites` (ссылки в Mini App).

### 5.3. Онбординг и deep links

Первый `/start` — приветствие + пример запроса + меню; повторный —
«С возвращением» + shortcuts (AI-подбор, приложение, фильтры, избранное).
Deep links (сейчас только логируются — **доделать**):
- `?start=listing_{id}` → карточка объявления (sendPhoto + inline-кнопки).
- `?start=filter_{id}` → фильтр.
- `?start=ref_{user_id}` → записать реферера **[бэкенд]**.
- `?start=app` → открыть Mini App.

### 5.4. AI-диалог

Как сейчас: текст → backend → GLM-агент, кнопки-опции в FSM, «🔎 Искать»,
«🔄 Сбросить». Улучшения: критерии человеко-читаемым текстом (не JSON),
`send_chat_action("typing")` перед запросом LLM, превью находок до
финализации. Лимиты по тарифу (Free 20/день) + апселл Pro.

### 5.5. Карточка объявления в боте

`sendPhoto` (первое фото, caption с ценой/пробегом/локацией/источником;
без фото — текст). Кнопки: Mini App (фото/детали), ❤️ избранное,
📞 Связаться (→ `POST /api/leads`), ➡️ Ещё.

### 5.6. Уведомления

Instant (новое по instant-фильтру), digest 09:00/20:00, price drop
**[бэкенд]**, системные (подписка истекает за 3 дня/1 день/после).
Антидубли: `notified:{uid}:{lid}` TTL 7д. Тихие часы **[бэкенд]**.
Настройки — уже есть (`menu:notify`).

### 5.7. Оплата

Flow как реализовано: `prepare_payment` → `answer_invoice` (XTR) →
`pre_checkout_query` → `successful_payment` → активация через backend.
Напоминания о продлении — **[бэкенд: планировщик]**.

### 5.8. Чего НЕ делать в боте

Не дублировать Mini App; не больше 6 inline-кнопок; не заставлять помнить
команды; не слать длинные сообщения; не спамить instant-уведомлениями.

### 5.9. Форматирование

HTML (уже используется), эмодзи для структуры, длина 500–1000 символов,
ссылки inline.

## 6. Контент и тон голоса

### 6.1. Тон

- **B2C (Mini App, бот):** дружелюбно, коротко, конкретно; «вы» с маленькой.
- **B2B (партнёрский ЛК):** деловой, точные термины (claim, acceptance rate);
  «Вы» с большой.
- **Админка:** технический, без эмодзи в текстах, полные термины.

### 6.2. Микротексты

Кнопки: «🔎 Запустить поиск», «Уточнить», «🔄 Сбросить», «📞 Связаться»,
«❤️ / 💔», «➡️ Ещё», «← Назад», «Отмена», «Сохранить», «Удалить», «Подтвердить».

Empty states: Feed — «Ничего не найдено. Попробуйте изменить фильтры»;
Favorites — «Здесь пока пусто»; Filters — «Создайте первый фильтр — и
получайте уведомления»; AI — «Опишите, какой авто ищете…»; пул партнёра —
«Нет доступных лидов. Проверьте позже».

Errors: сеть — «Не удалось загрузить. Проверьте соединение»; LLM — «AI
временно недоступен. Используйте фильтры»; 429 — «Слишком много запросов»;
401 — «Сессия истекла. Войдите заново»; 500 — «Что-то пошло не так».

Успехи: «✅ Заявка отправлена. Менеджер свяжется в течение 15 минут»;
«❤️ Добавлено в избранное»; «⭐ Pro активирован до {date}»; «✅ Фильтр
сохранён»; «✅ Лид захвачен».

### 6.3. Избегать

«Уважаемый пользователь», «мы рады сообщить», голые коды ошибок, CAPS LOCK,
много эмодзи.

### 6.4. Локализация

MVP — русский. Позже: en, kk, be (react-i18next + JSON-словари; у бота —
свой словарь).

## 7. Чеклист внедрения

### 7.1. Приоритеты

**P0 (Mini App polish):** фото в Feed/Listing; skeleton; тосты; динамические
чипсы; SVG-таббар; адаптив; онбординг 3 шага + `users.onboarded_at`; deep
links в боте.

**P1 (Партнёрский ЛК):** вход по ключу; дашборд; пул + claim; мои лиды +
feedback; API-ключ.

**P2 (Админка):** вход по internal token; дашборд; источники; партнёры; лиды;
юзеры; аналитика.

**P3 (AI-помощник):** agent loop; tools админа/партнёра; чат-виджет; audit
log (`admin_actions`) **[бэкенд]**.

**P4 (polish):** калькулятор «под ключ»; похожие; история цен; рефералка;
экспорт данных; i18n; биллинг партнёров **[бэкенд]**.

### 7.2. Метрики UX

Time to first result < 30 сек; activation > 40%; retention D1 > 30%, D7 >
15%; conversion to lead > 5%; partner claim rate > 70%; partner acceptance
rate > 60%.

### 7.3. Критерии готовности

Все экраны работают на мобильном и десктопе; нет Spinner-заглушек (только
skeleton); ошибки — тостами; действия — с haptic; empty/error states везде;
партнёр claim-ит лиды без curl; админ управляет источниками без curl;
audit log пишется.
